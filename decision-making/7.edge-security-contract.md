# 应用与边缘的安全分工

## 背景

一组安全性质由 Cloudflare、nginx、Next 三层共同决定，仓库里只有 Next 这一层。分工以前没有写下来，应用代码里于是有几处依赖边缘行为、却看不出自己依赖什么的假设（`CF-Connecting-IP` 优先、OIDC provider 信任转发头、`/api/upload/*` 不受 proxy 的 CSRF 保护），每轮评审也要向站长重复问同一组运维问题。

本文把分工写定：应用能自己保证的性质收回应用，配测试（第一部分）；只能由边缘保证的写成义务，由站长逐条作答（第二部分）。仓库是公开的，所以本文只写义务、依赖它的代码与不成立时的后果，**不写答复**：「源站能不能被绕过 Cloudflare 直连」这类答复连同代码里的取址规则放在一起，就是公开的绕过说明。答复与生产实测记在站长自己的私有记录里（本地工作区的 `docs/` 不进仓库）。以后新代码要依赖边缘行为（客户端 IP、转发头、缓存、注入脚本、安全头）时，先对照本文；分工变了，同步改本文。

## 拓扑

```
浏览器 → Cloudflare → nginx → PM2：Next standalone
                              ├─ kun-touchgal-next       16 个 cluster 实例，127.0.0.1:3000
                              └─ kun-touchgal-next-cron  1 个实例，127.0.0.1:3001
对象存储：浏览器 → Cloudflare → Backblaze B2（图片与资源文件同一主机名、同一个桶）
```

- 站点主域 `https://www.touchgal.ink`（`config/moyu-moe.ts`）；`OIDC_ISSUER` 是 `<主域>/oidc`，每个环境各有一个。
- 应用进程绑在 `127.0.0.1`（`ecosystem.config.cjs`），看不到 TCP 对端：凡是要知道「这个请求真的从哪来」的判断，只有 nginx 能做。

## 一、应用自己保证的性质

| 性质                                                                                                                                                                                                                               | 代码                                                                          | 测试                                                                            |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| 全站响应带 `X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy: strict-origin-when-cross-origin`、`Permissions-Policy: camera=(), microphone=(), geolocation=(), browsing-topics=()`；不发 `X-Powered-By` | `config/security-headers.ts`、`next.config.ts`                                | `config/__tests__/security-headers.test.ts`                                     |
| OIDC 的 discovery 端点、交互的跳转地址、会话 cookie 的 `Secure` 只由 `OIDC_ISSUER` 决定，与请求带来的 `Host`、`X-Forwarded-*` 无关（provider 不开 `proxy`）                                                                        | `lib/oidc/webToNode.ts` 的 `normalizeOidcRequestView`、`lib/oidc/provider.ts` | `lib/oidc/__tests__/webToNode.test.ts`                                          |
| `/api` 下全部写方法（含 `/api/upload/*`）经 proxy 校验 CSRF；唯一豁免 `/api/user/setting/email/revert`（邮件链接里的一次性令牌）                                                                                                   | `proxy.ts`、`middleware/_csrf.ts`                                             | `middleware/__tests__/proxy-csrf.test.ts`、`middleware/__tests__/_csrf.test.ts` |

安全头模块刻意不写的四个头：

- `Cache-Control`：游客 RSC 的缓存规则只归 `config/rsc-cache-headers.ts`。
- `Content-Security-Policy`：响应头的优先级是 proxy > `headers()` > route handler，放进 `headers()` 会盖掉路由自设的 CSP；oidc-provider 也只在响应里已有 CSP 时才给 `form_post` 的内联脚本追加哈希。将来的 CSP 只能由 proxy 与 OIDC 桥设置（见第四部分）。
- `Strict-Transport-Security`：是整个域名的决定，归边缘（第二部分③）。
- `Cross-Origin-Opener-Policy`：会切断依赖方用弹窗登录时依赖的 `opener`。

`X-Frame-Options` 取 `DENY`：仓库里没有按 URL 嵌入本站页面的地方（后台邮件预览是 `srcdoc`，不受它约束）。OIDC 的 `/oidc/*` 也在内。它只作用于 iframe 里最终渲染的响应，不作用于跳转：`prompt=none` 以 303 跳回依赖方，不受影响；被拦下的只有 provider 在 iframe 里输出的 HTML，其中会影响正常流程的是 `response_mode=form_post` 的自动提交页。另外 provider 的会话 cookie 与站点会话 cookie 都是 `SameSite=Lax`，跨站依赖方（如 `bbs.touchgal.co`）的 iframe 本来就带不上会话。所以只有同站依赖方（`*.touchgal.ink`）在 iframe 里用 `form_post` 时才需要把 `/oidc/:path*` 从规则里排除，届时在这里记一笔。

## 二、边缘的义务（站长逐条作答）

答复写在私有记录里，每条带答复日期与核实方式（见上文「背景」）。没有答复的，按「不成立」理解它的后果。

**① 源站是否只接受 Cloudflare 回源**（防火墙只放行 Cloudflare 网段，或开 Authenticated Origin Pulls）

- 依赖它的代码：`app/api/utils/getRemoteIp.ts` 无条件优先信 `CF-Connecting-IP`，登录、注册、2FA、改密与改邮箱、发信冷却、下载去重都按它计数（调用点 `git grep -n 'getRemoteIp('`）。
- 不成立时：能直连源站的人可以伪造 IP，绕过按 IP 的限频。后果有界：2FA 另有按账号的预算，发信先过人机验证、有按邮箱的冷却，下载去重被绕过只会虚增计数。

**② nginx 对 `X-Forwarded-For`、`X-Forwarded-Host`、`X-Forwarded-Proto`、`X-Real-IP` 是覆盖写还是追加**（`$proxy_add_x_forwarded_for` 是追加）

- 依赖它的代码：`getRemoteIp` 在没有 `CF-Connecting-IP` 时退到 `X-Forwarded-For` 的首段、再退到 `X-Real-IP`。Next 对 `x-forwarded-*` 只在缺失时补齐，不覆盖客户端带来的值。OIDC 已经不依赖这一条。

**③ HSTS 由谁下发**（Cloudflare SSL/TLS → Edge Certificates，或 nginx `add_header`），`max-age`、`includeSubDomains`、`preload` 各是什么；是否开了 Always Use HTTPS

- 应用不下发 HSTS。

**④ Cloudflare 是否缓存 HTML 或 `/oidc/.well-known/*`**（Cache Rules、Page Rules 的 Cache Everything）

- 依赖它的代码：游客 RSC 的 `private, no-cache` 规则按浏览器语义写；暂缓中的 nonce CSP 不能用在被缓存的 HTML 上。

**⑤ 是否开了会向 HTML 注入脚本的功能**（Rocket Loader、Email Address Obfuscation、JS Detections / Bot Fight Mode、Web Analytics 自动注入、Zaraz）

- 依赖它的代码：暂缓中的 nonce CSP 要么放行这些脚本，要么关掉它们。

**⑥ Transform Rules 或 nginx 是否另外下发了安全头**（`X-Frame-Options`、`X-Content-Type-Options`、`Referrer-Policy`、`Permissions-Policy`、CSP），取值与第一部分是否冲突

- `X-Frame-Options` 出现两个不同的值时，浏览器按拒绝处理；重复的头按第一部分为准清掉边缘那份。发布后按第三部分第 1 项核对。

**⑦ 对象存储的公开主机名是不是独立的可注册域**（与 `www.touchgal.ink` 跨站）

- 依赖它的代码：资源文件的字节由上传者决定。与主站同站时，那里托管的 HTML 发往主站的请求会带上 `SameSite=Lax` 的会话 cookie，还能给父域写 cookie；跨站时都不能。资源路径上要下发的响应头与拦截规则见 `AGENTS.md`「对象存储的桶与边缘配置」。

**⑧ nginx 的 `client_max_body_size` 与 Cloudflare 的请求体上限各是多少**

- 依赖它的代码：`/api` 的请求体在交给 handler 之前被 Next 收完整段，超过 10 MiB（`constants/bodyBudget.ts` 的 `KUN_PROXY_BODY_CLONE_LIMIT`）的部分读掉丢弃，各入口再按自己声明的预算拒绝（`lib/http/readBody.ts`）。`/oidc/*` 不经 proxy：桥按 64 KiB 的预算边读边计数（`lib/oidc/webToNode.ts` 的 `buildRequestBridge`），超出回 413、不进 provider。每个请求占用的内存应用自己已有上界，这一条决定的是超大请求在被拒绝之前要占多少带宽与连接时间，属纵深防御。

## 三、核对清单

Cloudflare 会用质询拦下 `curl`，以下都在浏览器 DevTools 里看（Network 面板选中请求看 Response Headers；Application → Cookies 看 cookie）。

1. 主文档 `/`：第一部分的四个头各出现一次，没有 `X-Powered-By`，没有边缘重复下发的同名头（⑥）。
2. 游客在站内点一次跳转：`_rsc` 请求仍是 `Cache-Control: private, no-cache`。
3. `/oidc/.well-known/openid-configuration`：`issuer`、全部 `*_endpoint` 与 `jwks_uri` 都以 `OIDC_ISSUER` 开头。
4. 从依赖方走一次完整登录：成功回到依赖方，`_touchgal_oidc_session` 带 `Secure`。
5. 人机验证、邮箱变更的撤销页（邮件里的链接，表单提交）、创作者账号上传一次资源（`/api/upload/init`、`/api/upload/complete` 都是 200）各走一次。

## 四、暂缓项与重启条件

**按请求 nonce 的 CSP**（含 proxy 的 matcher 扩到全部页面、`/api/csp-report`）

- 重启条件，任一成立：④⑤ 得到答复；页面里注入 HTML 的地方再出现 XSS 类缺陷；与收拢富文本承载组件同期立项。
- 重启时必须带上的修正：CSP 不进 `headers()`；`/oidc/interaction` 页与 provider 自己输出的 HTML 用不含 `form-action` 的变体，由桥在调用 provider 之前设置 CSP，让 provider 自己追加哈希；`connect-src` 包含 S3 端点（`components/patch/resource/upload/FileUploadContainer.tsx` 的直传）与站点源；Plyr 的 `iconUrl` 改为自托管（默认指向 `cdn.plyr.io`）；客户端给 zod 设 `jitless`（它用 `new Function` 做探测）；`worker-src` 加 `blob:`，`script-src` 加 `'wasm-unsafe-eval'`（人机验证要用）；`frame-src` 放行 `forms.office.com`（`posts/notice/survey.mdx`）；`/doc` 用静态变体；matcher 扩张之前先给 `middleware/auth.ts` 的前缀判断加路径边界，并把 `middleware/__tests__/auth-matcher.test.ts` 改写成 `unstable_doesMiddlewareMatch` 的行为断言。

**可信代理开关 `KUN_TRUSTED_PROXY`**

- 不做的原因：应用看不到对端，环境变量验证不了它声明的信任关系；源站能不能被直连只能由 nginx 的 `real_ip` / 防火墙或 Authenticated Origin Pulls 决定。
- 重启条件，任一成立：① 答「否」；客户端 IP 成为匿名写入频率预算的主键（目前 `server/abuse/` 只按账号计）。
- 届时的做法：nginx 用 `real_ip` 校验 Cloudflare 网段后覆盖写 `X-Real-IP`，应用只读这一个头并用 `isIP` 校验。
